# handraw-style 深度集成：风格路由、编号校验与出图工作流（v1.3.0）

原项目：**yang0/handraw-style**，地址 <https://github.com/yang0/handraw-style>，许可证要求保留原作者与原仓库署名。本 Skill 提供互操作适配层，**不把 400MB+ 的全部参考图片塞进写作技能包**，也不冒充拥有上游完整图库。上游完整资源安装在用户环境时可按需引用；用户指定风格时可以读取其权威目录。此集成不会代替上游项目，也不会在未经明确授权时调用上游社区分享或上传逻辑。

## 1. 请求优先级（每一张图独立判断）

1. 用户明确指定的画风编号、图型编号、主题色：最高优先级；只改用户没有指定的维度。
2. 用户提供自己的参考风格图片（可能优先于编号；若与编号矛盾，先说明冲突）。
3. 当前账号品牌素材与品牌色：默认启用真实 3D IP、Logo、公众号名，除非用户显式关闭。
4. 未指定编号：**实时根据文章思想、读者情绪、视觉隐喻、封面阅读尺寸、正文图像职能挑选**；不得维护“AI 文章固定选 169”之类主题到风格硬编码表。
5. 全篇统一：封面与正文优先共用一组编号与配色，但可以同风格不同构图/信息密度。更换风格前征得用户允许。

上游支持历史编号 `001–370` 与新 ID `FA-001` 等，二者通过其 `style_alias_map.json` 对照。**不能根据编号大小推测所属分类**（例如历史编号 `169` 的当前映射是 `FH-015`，不是直接 `FH-169`）。用户指定无效或未索引编号，必须回到真实仓库查询或要求用户提供目录，绝不捏造定义。

## 2. 权威资料按需读取

- 首先使用宿主可用的 GitHub 连接或读取已安装的上游根目录，查看 `SKILL.md` 和对应 `skills/handdraw-style-prompter/SKILL.md`；只采用与公众号图片相关的功能。
- 画风：`styles_200_reorganized.md`（权威文字描述）、`skills/handdraw-style-prompter/references/style_alias_map.json`（编号映射）；可查看 `STYLES.md` 示例。
- 图型：`LAYOUTS.md` 与 `skills/handdraw-style-prompter/references/layouts/` 中权威版式提示词，若不知道图型说明不要编造。
- 颜色：`COLORS.md`（C-01～C-36）。
- 封面方法：`skills/article-cover-designer/SKILL.md`；插图规划：`skills/article-illustration-planner/SKILL.md`。但作者写作规则、隐私规则和用户确认机制始终以本 Skill 为准。

本地标准库桥接工具：`python scripts/handraw_bridge.py --style 169 --theme 'AI 工具越多，为什么事情反而没做完？' --usage cover --color C-01`。

桥接脚本离线自带已核验的小型精选库：`169/FH-015` 彩铅日记、`167/FH-013` 双色孔版手绘、`175/FH-021` 墨线点色、`018/FA-018` 极简冷幽默、`013/FA-013` 粗线社论。**其他任意编号的完整支持**请提供 `--upstream /path/to/handraw-style`（已安装原仓库）；无目录则通过 GitHub 连接读取，不得回退随机风格。

完整上游仓库需要用户另行克隆/安装：`python scripts/install_handraw_upstream.py --mode catalog`（少量文字索引）或 `--mode full`（大型图库）。也可手动运行 `git clone --depth 1 https://github.com/yang0/handraw-style.git`。原仓库体积较大，安装前告知用户会下载参考图库。无需为使用随包已有几个示例风格而安装上游仓库。上游项目的模型和图库不等于图像生成服务，出图仍需当前可用工具。

## 3. 公众号封面（同写作工作流阶段 8）

- 摘要不超过约 200 字；提炼反常识冲突、视觉隐喻、目标人群。
- **先设计隐喻再出图，主标题明显，小字少或没有小字。** 默认画幅 `2.35:1`，用户指定则改；检查上下边缘安全留白以及公众号实际后台裁切。
- 默认：真实个人 3D IP 保留发型、五官、服装、胸前标识，作为精致“角色贴纸”与手绘场景混合；不把整个原人像重新生成成“陌生的孩子”。
- Logo、公众号字标**直接叠加原素材文件**，不要依靠 AI 猜 Logo。可以用本地合成、图像编辑工具实现，必须检查源文件与成图一致性。
- 视觉密度：一个主要隐喻 + 一组标题 + 一个品牌角色 + 小标识；反对办公桌、咖啡杯、机器人、窗口浮层满屏堆砌，标题不能被人物遮挡。
- 手绘风格不是“必须粗糙”：遵照选定的线条、纸纹、颜色与构图，不主动加入塑料立体 UI。

## 4. 正文配图

- 首先判断文章体裁：知识/流程文章优先概念图、结构图、对比图；观点叙事文章优先概念隐喻和必要节奏图。
- 根据正文结构选择 **0–4** 张，拒绝固定“每隔 500 字一张”；每张都有**准确插入锚点**、图片任务、视觉构思、尺寸（正文建议 `4:3`）、alt 文本、风格 ID/色彩 ID、提示词。
- 真实数据、公式和业务事实不得虚构；图替繁文必须在获得 L2/L3 权限后才改变正文文字。
- 同一篇文章图片按固定风格、色盘与IP参照，正文可不出现个人角色（例如流程图优先信息可读性）。
- 真正生成后才执行回填；需要给用户交付图片文件或带相对路径的 Markdown，并对公众号实际图片上传/粘贴方式提示。

## 5. 出图工具与失败策略

有可用图像生成工具时，在用户明确要求出图的前提下使用它；无权限、无额度或工具不可用时，交付真实可用的提示词/风格包。若能使用本地图形工具绘制手绘效果与原图合成，可如实交付本地合成的 PNG，**不能称其为模型参考图驱动的高保真生成**。风格参考图缺失时不要假装已经传入。

只有当上游自带 `images/individual/` 里的编号参考图确实存在并被送入生成工具，才可记录 `style_reference_used=true`；否则记录 `false`。对需要使用参考垫图的模型，若无参考图则报告限制，不作 100% 风格一致保证。

## 6. 用户指定示例

- `指定 handraw 169 号，封面加我的 3D IP，正文同风格配图 2 张。`
- `图型 IG-013、风格 FH-015、主题色 C-01，用在文章的流程段落。`
- `不指定编号，你根据文章主题自动挑风格，并告诉我选它的原因。`
- `这篇用我刚上传的新形象，不要用小康新鲜事儿的默认素材。`
