# 工作流状态与确认协议

- `stage`：0 到 9；`mode`：standard/quick/demo。
- `state`：needs_input, proposed, pending_confirmation, confirmed, blocked, delivered。
- 每一阶段把用户已确认的原始材料和待确认点分开整理；作者可说“退回选题”“不要这段”“只改错字”。
- 在 `pending_confirmation` 状态，不允许因为用户沉默自动推进；用户一句“可以/按这个来”仅确认**当前展示的阶段产物**。
- 用户要求跳到后续阶段时可以跳过可选部分，但应提示材料不足与质量风险；不得自行编造缺失事实。
- 模式变更必须由用户意图触发，不能为了省事把标准共创默默换成自动代写。

## 演示模式限制

演示可以自动为测试 fixture 填充模拟大纲与素材，并生成正文、标题、摘要、排版，但要清楚列出**模拟输入**与**未取得真实用户确认**。这验证的是规则和输出能力，不是证明真实用户愿意发表或真实点击效果。

## 异常与恢复

- 没网络：不能验证热点，改用常青题或用户提供素材。
- 没知识库：明确未连接，请用户提供，不虚构检索结果。
- 没语音稿：允许键入碎片或完整初稿。
- 有完整初稿：询问或推断其明确意图，采用 L1 默认；若要扩写，明确询问。
- 断点恢复：复述最后已确认阶段、下一步需要内容，不要求重新从第一步开始。
